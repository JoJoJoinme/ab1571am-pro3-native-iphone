# Pro 3 原生 iPhone 功能固件复现与刷写指南

本指南对应 2026 年 11 月 14—15 日的一次单设备实验。该副 Pro 3 已由设备所有者确认：佩戴后可在 iPhone 原生设置切换降噪／通透，耳机柄切换能同步页面；开启设备信息上报并在 iPhone 忽略设备、重新配对后，顶部图片、卡片和连接弹窗出现。充电仓电量通常只在取出耳机、配对时显示，其他时候大多不显示，与 Pro 2 不同，尚未解决。

公开附件提供离线补丁工具、校验工具和 Android 辅助程序源码。使用者必须读取自己的双耳备份并通过精确校验，才能生成升级包。完整实测镜像含设备标识，单独作为私人留档，不在公开附件中分发。

# 适用范围与停止条件

这是一份给熟悉 ADB、Android 构建和固件验证的技术用户使用的复现指南。相同芯片、名称、外壳或版本文字不能代替镜像匹配；Pro 2 的程序也不能用于 Pro 3。本案例没有验证断电救砖或真机回退，没有确认充电盒 USB 可作为烧录接口。

已验证的软件身份为 `ab157x_evk`，SDK 为 `IoT_SDK_for_BT_Audio_V3.10.0.c43sp_YFY_1`，构建时间 `2026/10/12 15:44:12 GMT +08:00`，升级接口版本 `V310.1.865.11`。原始主控分区位于 Flash 偏移 `0x001CA000`，长度 `2,351,104` 字节；完整 Flash 为 `8,388,608` 字节。

```text
原始 MCU SHA-256
4618fb38ff33a8453ced99e3d797b6ebd5f841039748116d7cc2bf6c7a474fb4

修改后 MCU SHA-256
4e472427dbb9c277a4ea030b2bf383a53e2c030ebd10f5d624e0dbab48c7b9e7

升级包 SHA-256
5a9360a8abdda8231852985c5959d72b031e49bed0cdc84fa4b080e4b39796dc

原版 MCU 回退包 SHA-256
eb27b920ee9bd52a9b3fa9a3f8ac024e34d4e035d5228eb0d2f7e3020e23df46
```

任一镜像、启动程序、DSP、分区布局、设备身份或双耳状态不符，就停止当前流程并单独分析。不要改掉哈希检查、用另一副耳机的备份顶替，或把下面的缓存地址套到别的固件。

# 本次改动的具体范围

主控补丁将镜像偏移 `0x99B1A` 的一个字节由 `00` 改为 `01`，把一条 `MOVS r0, #0` 改成 `MOVS r0, #1`。升级包只搬运主控分区，保留版本文字，采用未压缩载荷和 SHA-256 校验。它不包含 DSP 或 NVDM 配置区更新。

设备信息上报是另一步操作：双耳 `FB00` 从 `00` 改为 `01`，并将当前构建中 `0x1423B29D` 的运行标志同步为 `01`。实际读写按对齐的四字节地址 `0x1423B29C` 进行，另外三个字节必须保留并核对。成功案例中的 `FC04=00`、`FB03=01` 没有改变；不要把旧构建案例中的数值清单照搬过来。

# 准备工具并绑定自己的耳机

准备 Windows、Python 3.10 或更新版本、JDK 17 或更新版本、Android SDK Platform 35、Android Build Tools，以及 ADB。手机需要 Android 13 或更新版本；实机流程是在一加 Android 13 上完成的。双耳保持开机，电量均至少 60%，先连接到用于操作的安卓手机。

辅助程序按你自己的耳机蓝牙地址和名称构建。占位地址不能照抄，蓝牙地址需要从本机已配对设备的信息中确认。源码中的升级程序保留了双耳状态、电量、分区、包哈希与提交检查；转交版另加了实际主控哈希检查。转交源码已完成构建与离线校验，没有再次用工作中的耳机做重复刷写。

```powershell
$Adb = 'C:\Android\platform-tools\adb.exe'
$Phone = '你的 ADB 设备标识'
$EarbudAddress = 'AA:BB:CC:DD:EE:FF'
$EarbudName = '你的耳机蓝牙名称'

& $Adb devices -l
python .\tools\fetch_sdk.py
python .\tools\build_helpers.py --android-sdk 'C:\Android\Sdk' --address $EarbudAddress --name $EarbudName

& $Adb -s $Phone install .\generated-apks\readonly.apk
& $Adb -s $Phone install .\generated-apks\fota.apk
& $Adb -s $Phone install .\generated-apks\metadata.apk
```

首次打开辅助程序时，在 Android 的正常权限窗口允许“附近的设备”。如果系统不允许通过 ADB 授权，不要绕过系统限制，使用应用权限窗口即可。构建生成的 APK、签名文件和下载的厂商库保留在自己的电脑上，不要把绑定了设备地址的 APK 当作通用安装包再分发。

# 先读取并验证自己的双耳备份

先做配置查询，核对平台、构建和双耳响应。随后分两次读取连接耳与发现的另一耳。两次备份期间避免换耳、入仓或主动切换连接角色；这两个逻辑名称不能直接当作固定左耳和右耳。

```powershell
& $Adb -s $Phone shell am start -n org.earbud.repro.readonly/.MainActivity --es mode read-config --es address $EarbudAddress

& $Adb -s $Phone shell am start -n org.earbud.repro.readonly/.MainActivity --es mode backup --es address $EarbudAddress --es start 0x08000000 --ei size 8388608 --ei window 4 --ez peer false
```

等到第一份日志明确显示 `BACKUP COMPLETE`，并确认会话已结束，再读取另一耳。出现超时或 `.partial` 文件不算备份完成。

```powershell
& $Adb -s $Phone shell am start -n org.earbud.repro.readonly/.MainActivity --es mode backup --es address $EarbudAddress --es start 0x08000000 --ei size 8388608 --ei window 4 --ez peer true

& $Adb -s $Phone shell run-as org.earbud.repro.readonly ls files
```

从列表中找到两份完整 `.bin` 和各自同名的 `.json`。下面的文件名必须换成实际输出的名字。使用附件的二进制传输工具导出，避免 PowerShell 文本重定向或标准输入转发损坏二进制数据。

```powershell
python .\tools\phone_file.py --adb $Adb --serial $Phone --app readonly pull --name '实际连接耳备份.bin' --out .\own\connected.bin
python .\tools\phone_file.py --adb $Adb --serial $Phone --app readonly pull --name '实际连接耳备份.json' --out .\own\connected.json
python .\tools\phone_file.py --adb $Adb --serial $Phone --app readonly pull --name '实际另一耳备份.bin' --out .\own\peer.bin
python .\tools\phone_file.py --adb $Adb --serial $Phone --app readonly pull --name '实际另一耳备份.json' --out .\own\peer.json
```

保留这些文件的独立副本。工具会检查每份文件的大小、手机端清单、完整哈希、主控、启动程序、DSP、关键分区与 NVDM 记录校验。原始备份包含配对、校准和设备身份数据，不随文章公开。

# 从自己的备份生成升级包

```powershell
python .\tools\firmware_tool.py generate --connected .\own\connected.bin --connected-manifest .\own\connected.json --peer .\own\peer.bin --peer-manifest .\own\peer.json --out .\generated

python .\tools\firmware_tool.py verify-package .\generated\pro3-apple-native.fota.bin
python .\tools\firmware_tool.py verify-package .\generated\pro3-original-rollback.fota.bin
```

生成结果必须与本指南列出的包哈希一致。工具拒绝未知镜像、已修改镜像以及不匹配的备份。输出目录中的 `build-result.json` 是自己的本地记录；生成的固件也可能含原厂写入的设备标识，应保留为私人文件。

# 暂存双耳升级包并单独提交

先打开升级辅助程序执行检查。这一步不能省略：它读取双耳状态、版本、电量、升级分区与实际主控哈希。正常升级要求两耳主控均为本指南的原始哈希、版本一致、状态为已识别的空闲状态，并且两耳电量都达标。

```powershell
& $Adb -s $Phone shell am start -n org.earbud.repro.fota/.MainActivity --es action inspect

python .\tools\phone_file.py --adb $Adb --serial $Phone --app fota push --file .\generated\pro3-apple-native.fota.bin --name candidate.fota.bin
```

等日志出现 `ACTIVE_MCU_PREFLIGHT_OK`，确认所有检查通过，再开始暂存。程序会先处理一耳，经过角色切换再处理另一耳。`TRANSFER_COMPLETE` 表示传输阶段完成，尚不是新固件已经运行。

```powershell
& $Adb -s $Phone shell am start -n org.earbud.repro.fota/.MainActivity --es action stage
```

等到双耳状态均为 `0x0311`，且日志出现 `TRANSFER_COMPLETE`，再请求两耳分别计算整个暂存文件的哈希。必须看到两次 `STAGED_HASH_MATCH` 和 `VERIFICATION_COMPLETE`，且校验值等于升级包哈希。

```powershell
& $Adb -s $Phone shell am start -n org.earbud.repro.fota/.MainActivity --es action verify

# 上述双耳验证确实通过后，仅提交一次
& $Adb -s $Phone shell am start -n org.earbud.repro.fota/.MainActivity --es action commit --es verified_hash 5a9360a8abdda8231852985c5959d72b031e49bed0cdc84fa4b080e4b39796dc
```

提交后等待设备完成更新、重启和重新连接。若响应丢失或连接异常，不要重复提交，也不要靠重启工具来反复尝试；保留日志，先查明设备实际状态。蓝牙服务未恢复时，原版文件本身不提供有线救砖能力。

# 重启后验证实际主控分区

确认双耳完成并重新连接后，结束升级辅助程序，再用只读程序独立查询两耳实际主控分区。两个结果都必须匹配修改版 MCU 哈希。不要用暂存文件校验、进度 100% 或工具退出状态替代这一步。

```powershell
& $Adb -s $Phone shell am force-stop org.earbud.repro.fota
& $Adb -s $Phone shell am start -n org.earbud.repro.readonly/.MainActivity --es mode read-active-hashes --es address $EarbudAddress
```

# 单独启用设备信息上报

主控验证通过后，先读取双耳当前配置与运行缓存，并导出基线。只有设备信息已加载、缓存状态符合当前构建、两耳主控哈希均正确时，才执行调整。

```powershell
& $Adb -s $Phone shell am start -n org.earbud.repro.metadata/.MainActivity --es mode inspect

# 等 BASELINE_SAVED 和 END completed 后导出
python .\tools\phone_file.py --adb $Adb --serial $Phone --app metadata pull --name metadata-baseline.json --out .\own\metadata-baseline.json

& $Adb -s $Phone shell am start -n org.earbud.repro.metadata/.MainActivity --es mode apply
```

成功标准为 `APPLY_COMPLETE`，且连接耳、另一耳分别读回 `persistent_fb00=1`、`runtime_fb00=1`。程序还检查相邻三个缓存字节、FC04、FB03 和两耳主控哈希。本实验在这一步共发送四条修改指令：每耳一条配置写入、一条缓存同步。

```powershell
python .\tools\phone_file.py --adb $Adb --serial $Phone --app metadata pull --name metadata-result.json --out .\own\metadata-result.json
& $Adb -s $Phone shell am force-stop org.earbud.repro.metadata
```

# 在 iPhone 上重新配对并验收

在 iPhone 中对目标耳机选择“忽略此设备”，再重新配对。成功案例中，仅断开重连没有恢复顶部卡片；重新配对后，图片、电量卡片和连接弹窗才出现。这个观察不能扩展成已经定位了 iOS 内部缓存的具体故障。

佩戴双耳后检查：原生降噪／通透切换是否实际改变声音；长按耳机柄切换时页面是否更新；顶部耳机和充电仓图片及可获取的电量是否显示；开盒靠近连接时是否出现弹窗。耳机留在充电仓里的切换回跳，不能直接作为佩戴状态下的功能失败。

本案例最终保持 `FC04=00`、`FB03=01`、`FB00=01`，加上单字节主控补丁。没有为了弹窗再把 FB03 改成旧研究中的值。图片、菜单或字符串出现也不能单独证明心率、精确查找、跨设备自动切换等全部高级功能。

# 回退范围与已知限制

附件工具生成的原版回退包只恢复原始 MCU，不会撤销 FB00 等配置调整。它通过了离线启动程序检查，但本案例没有执行真机回退。设备仍可正常连接、两耳实际主控均匹配修改版，且更新状态符合工具检查时，可按同样的暂存、双耳哈希验证与单次提交流程进行回退；第一步改用 `stage-rollback`，文件名为 `rollback.fota.bin`，提交哈希改为本指南的回退包哈希。不要把完整 8 MiB 备份当成 OTA 包导入。

如果要恢复配置，需要基于自己的 `metadata-baseline.json` 逐项分析；本工具没有提供未经本案例验证的通用配置回退或失联救砖操作。已知剩余问题是充电仓电量显示间歇，不能把卡片出现写成电量行为已完整恢复。跨设备兼容性和长期稳定性也没有由一次成功刷写得到保证。
